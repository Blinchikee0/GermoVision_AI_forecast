# Разбивка проекта на части

Проект разделён на **10 частей**. Каждая часть — самостоятельный модуль с чёткой границей: свой вход, свой выход, свои тесты. Часть считается готовой, когда проходят её тесты и выполнен критерий приёмки.

Порядок не произвольный: он определён зависимостями. Нельзя обучать модель, пока нет честного разделения выборки; нельзя мерить качество, пока нет метрик; нельзя строить оповещения, пока нет моделей.

---

## Карта зависимостей

```
 Ч1. ЯДРО ◄──────────────── фундамент, зависит от всех ничего
  │  типы · конфиг · сплиттеры · метрики · защита от утечек
  │
  ├──► Ч2. ДАННЫЕ
  │      загрузка CRyPTIC · каталог ВОЗ · признаки · Data Card
  │        │

  │                                          │
  └────────────────────────────────► Ч10. MLOPS / CI ◄─── охватывает всё
```

## Ч1. Ядро (`germovision.core`) — **текущая часть**

**Зачем первой.** Здесь живёт то, что делает проект научно корректным: разделение выборки и метрики. Если ошибиться здесь, ошибочными будут все результаты всех моделей. Именно в ядре исправляются главные дефекты версии 1.0 — утечка данных (D9) и отсутствие временнóй валидации (D11).

| Что входит | Файл |
|---|---|
| Типы и контракты данных | `core/types.py` |
| Конфигурация, сиды, детерминизм | `core/config.py` |
| Временнóе разделение + forward chaining | `core/splitting/temporal.py` |
| Разделение по кластерам родства | `core/splitting/cluster.py` |
| Leave-one-group-out (география) | `core/splitting/grouped.py` |
| **Защита от утечек** | `core/splitting/guards.py` |
| Метрики классификации + bootstrap ДИ | `core/metrics/classification.py` |
| Калибровка (Brier, ECE, кривая надёжности) | `core/metrics/calibration.py` |
| Метрики прогноза (log-loss, RPS, покрытие) | `core/metrics/forecasting.py` |
| **Lead Time** — главная метрика проекта | `core/metrics/leadtime.py` |
| Хеширование и происхождение данных | `core/provenance.py` |

**Вход:** ничего (базовый слой).
**Выход:** библиотека, которой пользуются все остальные части.

**Критерий приёмки:**
- все тесты проходят;
- `LeakageGuard` **падает** на намеренно испорченных данных (тест на то, что защита работает, а не молчит);
- метрики совпадают с эталонными значениями на синтетических примерах.

## Ч2. Данные (`germovision.data`)

| Что входит |
|---|
| Загрузчик CRyPTIC (геном + МИК по 13 препаратам) |
| Парсер каталога мутаций ВОЗ, 2-е изд. |
| Нормализация имён мутаций (`rpoB_S450L` в едином формате) |
| Построение матрицы признаков «изолят × мутация» |
| Контроль качества и фильтры |
| Кластеризация изолятов по родству (для сплиттера из Ч1) |
| Генерация Data Card |

**Вход:** сырые файлы источников.
**Выход:** `IsolateDataset` — таблица признаков + метки + метаданные + кластеры + даты.

**Критерий приёмки:** `make data` воспроизводит датасет с нуля, хеши совпадают; Data Card сгенерирована автоматически.

## Ч3. GV-Resist (`germovision.models.resist`)

| Что входит |
|---|
| Уровень 1: правила каталога ВОЗ (baseline и одновременно часть продакшна) |
| Уровень 2: градиентный бустинг на полном наборе признаков |
| Калибровка (изотоническая) |
| Механизм отказа от ответа (конформные предсказания + OOD) |
| Генератор объяснения: какие мутации привели к выводу |
| Отчёт по 13 препаратам с ДИ |

**Вход:** `IsolateDataset` из Ч2.
**Выход:** `ResistancePrediction` — вероятность + решение + обоснование + флаг достоверности.

**Критерий приёмки (гипотеза H1):** чувствительность ≥ 90 % и специфичность ≥ 95 % по рифампицину и изониазиду на внешней валидации leave-one-country-out — либо документированный отрицательный результат.

## Ч4. GV-Escape (`germovision.models.escape`)

| Что входит |
|---|
| Обёртка ESM-2, расчёт log-odds замен, кеширование |
| Структурные признаки (RSA, расстояние до эпитопа) из PDB/AlphaFold DB |
| Композиция риска: Fitness × Accessibility × Dissimilarity |
| Калибровка на DMS-данных |
| **Ретроспективный эксперимент по Омикрону** |

**Критерий приёмки (H2):** ROC-AUC ≥ 0,75 при строгой отсечке данных на 2021-06-30.

---

## Ч5. GV-Growth (`germovision.models.growth`)

| Что входит |
|---|
| Иерархическая байесовская мультиномиальная логистическая регрессия (NumPyro) |
| Четыре baseline: persistence, независимая логистическая, неиерархическая MLR, экспоненциальное сглаживание |
| Прогноз с интервалами на 2/4/8 недель |
| Проверка покрытия интервалов |

**Критерий приёмки (H3):** превосходство над persistence по log-loss; фактическое покрытие 95 %-х интервалов в диапазоне 92–97 %.

---

## Ч6. GV-Sentinel (`germovision.models.sentinel`)

| Что входит |
|---|
| Детектор аномальной длины ветви (пуассоновская статистика) |
| Детектор новизны в пространстве эмбеддингов (kNN / махаланобис) |
| Детектор всплеска ко-встречаемости (тест Фишера + поправка BH) |
| Пространственно-временное сканирование |
| Ансамблирование сигналов |

**Критерий приёмки:** обнаружение исторических событий (Альфа, Дельта, Омикрон) с положительным Lead Time при заданном бюджете тревог.

---

## Ч7. Fusion и оповещения (`germovision.fusion`)

| Что входит |
|---|
| Сборка объекта риска «вариант × регион × дата» |
| Калиброванный классификатор значимости |
| Выбор порога по бюджету ложных тревог |
| Три уровня оповещения (наблюдение / внимание / тревога) |
| Генератор объяснения оповещения |

**Критерий приёмки (H4):** положительный медианный Lead Time при соблюдении бюджета тревог.

---

## Ч8. API (`germovision.api`)

FastAPI: эндпоинты предсказания, статуса моделей, выгрузки отчётов; журналирование каждого заключения; экспорт HL7 FHIR.

**Критерий приёмки:** сквозной сценарий «геном → заключение» через HTTP; любое заключение восстановимо из журнала.

---

## Ч9. Интерфейс (`germovision.ui`)

Панель врача, панель эпидемиолога, карта, Mol\*-визуализация структуры. Streamlit — исследовательский режим, React — продакшн.

---

## Ч10. MLOps и CI

DVC, MLflow, GitHub Actions, мониторинг дрейфа, реестр моделей, автогенерация Model Card.

**Особое требование:** в CI работает тест, проверяющий порядок операций «разделение → аугментация». Он должен падать при попытке вернуть схему версии 1.0.

# GermoVision 2.0

**Система раннего предупреждения о клинически значимых мутациях патогенов**

> Мутации возникают случайно, но выживают закономерно.
> Предсказывать нужно не появление мутации, а её судьбу и её последствия.

---

## Быстрый старт

```bash
pip install -e ".[dev]"
python -m germovision.train --save-models models   # обучение и оценка, ~37 с
python -m germovision.dashboard                    # панель из полученных метрик
pytest tests -q                                    # 223 теста
```

Результат: `reports/metrics.json`, `reports/report.md`, `dashboard/index.html`, `models/`.

Система целиком — шесть экранов, локально:

```bash
python -m germovision.app --models models      # http://127.0.0.1:8000
```

Заключение по новому образцу из командной строки:

```bash
python -m germovision.predict --models models --mutations examples/data/sample_mutations.csv
```

## Что делает система

Система не пытается угадать, какая буква в геноме изменится, — это принципиально невозможно. Вместо этого она решает четыре задачи, каждая из которых научно обоснована и измерима:

| Модуль | Вопрос | Выход | Статус |
|---|---|---|---|
| **GV-Resist** | Устойчив ли изолят к препарату? | Прогноз по 13 препаратам за 1–2 дня вместо ~60 | ✅ реализован |
| **GV-Escape** | Насколько опасна замена, если она возникнет? | Ранжирование мутаций по эволюционному риску | ✅ реализован |
| **GV-Growth** | Вытесняет ли эта линия остальные? | Коэффициент роста β и прогноз доли на 2–8 недель | ✅ реализован |
| **GV-Sentinel** | Появилось ли что-то аномальное? | Раннее оповещение о необычных комбинациях | запланирован |

## Форматы: файл сам выбирает модель

Формат определяется **по содержимому, а не по расширению**, и направляется своей модели. Можно перетащить несколько файлов сразу — каждый обрабатывается отдельно, сбой одного не отменяет остальные.

| Что загружаете | Модель | Что получаете |
|---|---|---|
| Таблица мутаций `id, gene, mutation` | GV-Resist | Прогноз устойчивости по 13 препаратам |
| VCF с аннотацией snpEff | GV-Resist | То же, с разбором по образцам |
| Отчёт TB-Profiler (JSON) | GV-Resist | То же, напрямую из пайплайна |
| Белковые последовательности (FASTA) | GV-Escape | Мутации по убыванию риска, кандидаты, горячие точки |
| Нуклеотидные последовательности гена | GV-Escape | Трансляция и то же ранжирование |
| Счётчики линий `region, week, lineage, count` | GV-Growth | Коэффициенты роста и прогноз долей |

Геном целиком осознанно не принимается: вызов вариантов требует выравнивания на референс и контроля качества, то есть полноценного пайплайна. Система объясняет, чем его обработать, вместо того чтобы выдавать ненадёжный результат за готовый.

Результат каждой таблицы скачивается в CSV (с BOM — Excel открывает кириллицу правильно) или целиком в JSON.

## Система: шесть экранов

Интерфейс на английском — это язык надзора, каталога ВОЗ и международных
обозначений препаратов. Документация проекта остаётся на русском.

| Экран | Что на нём |
|---|---|
| **Overview** | Национальные индикаторы, активные сигналы, динамика линий, способность закрывать случаи по препаратам |
| **Analyze** | Перетаскивание файлов: формат определяется по содержимому и уходит своей модели |
| **Mutations** | Карта замен вдоль белка, ранжирование по риску, кандидаты, горячие точки |
| **Resistance** | Чувствительность по 13 препаратам на внешней валидации рядом с каталогом ВОЗ, доля МЛУ по странам |
| **Spread** | Доли линий по неделям, преимущество роста β по регионам с интервалами, прогноз |
| **Models** | Что делает каждая модель, протокол валидации, где системе нельзя доверять одной |

Загруженный файл меняет то, что показывает вся система: результат анализа
последовательностей попадает в Mutations, вариантов — в Resistance,
счётчиков — в Spread.

**Опубликованная версия** — та же система в статической сборке: те же экраны,
те же графики, но без загрузки файлов. Загрузка отправляла бы данные пациентов
на сервер, поэтому её там нет.

```bash
python -m germovision.dashboard    # собирает статическую версию одним файлом
```

### GV-Escape: что реализовано, а что нет

Современный подход к оценке риска мутаций — белковые языковые модели (ESM-2) и надстройки вроде EVEscape; они требуют десятков гигабайт весов и видеокарты. Реализован **классический профильный метод**: позиционно-специфичный профиль частот аминокислот.

Риск раскладывается на три множителя — та же схема, что в EVEscape: **допустимость** замены по профилю × **физико-химическая заметность** × **новизна**. Честное ограничение: профиль считает позиции независимыми и потому не видит эпистаз. Зато обучается за секунды на данных пользователя, не требует ускорителя и полностью объясним — вклад каждой компоненты виден в выдаче.

### GV-Resist: почему такая архитектура

**Два уровня, а не одна модель.** Каталог мутаций ВОЗ — официальный референсный стандарт, построенный на более чем 52 000 изолятов. Первый уровень применяет его правила: врач видит, что вывод соответствует стандарту, и может проверить логику. Второй уровень — градиентный бустинг — работает там, где каталог молчит: редкие варианты, их сочетания, недавно внедрённые препараты.

**Градиентный бустинг, а не нейросеть.** Данные табличные и разреженные, объём ~10⁴ объектов. В этом режиме бустинг не уступает нейросетям по качеству и превосходит по устойчивости, скорости и интерпретируемости. Нейросеть здесь была бы дефектом D13 версии 1.0 в новой обёртке.

**Модель обязана уметь молчать.** Отказ от ответа реализован через конформное предсказание с гарантией покрытия. Явный отказ отправляет образец на фенотипический тест — безопасный исход. Уверенная ошибка приводит к неверной терапии.

### GV-Growth: почему мультиномиальная модель

Результат надзора — счётчики: из N образцов за неделю столько-то относятся к каждой линии. Доли связаны условием нормировки, неопределённость зависит от объёма выборки, а логистический рост — следствие уравнений динамики отбора, а не подобранная кривая. Иерархическая структура позволяет региону с малой выборкой заимствовать силу у остальных; величина стягивания оценивается из данных.

## Данные

Гибридный пятислойный датасет: геномы (NCBI, GISAID, ENA) → эволюция (UniRef, ESM-2) → структура (PDB, AlphaFold DB) → фенотип (**CRyPTIC**, 12 289 изолятов, 13 препаратов; каталог мутаций ВОЗ 2-е изд.; DMS-карты Bloom lab) → эпидемиология (Nextstrain, WHO).

**Реальные данные подключаются так:**

```
data/cryptic/
    samples.csv     id, country, lineage, collection_date [, submission_date]
    mutations.csv   id, gene, mutation
    phenotypes.csv  id, drug, phenotype   (R/S либо 1/0)
```

```bash
python -m germovision.train --source data/cryptic --catalogue-tsv who_catalogue.tsv
```

Без них пайплайн работает на **синтетическом генераторе**, воспроизводящем структуру реальных данных: кластеры передачи, неполноту каталога, неполную пенетрантность, ошибку фенотипического теста, необъяснённую устойчивость, пропуски и временнóй дрейф. Метрики на синтетике характеризуют **корректность пайплайна, а не качество модели**, и помечены как синтетические на всём пути до панели.

## Что измеряет система

Две величины отвечают на вопрос «что это даёт», и обе считаются **от полного
числа изолятов**, а не от числа отвеченных — иначе отказ от трудных случаев
выглядел бы улучшением:

- **Верно закрыто** — доля изолятов, получивших правильный ответ за сутки вместо ~60 дней.
- **Пропущено устойчивости** — доля устойчивых, которым выдано уверенное «чувствителен». Единственный по-настоящему опасный исход.

Где доля пропусков выше клинического лимита, препарат помечается как требующий
лабораторного подтверждения, и пометка доходит до заключения врача. Система,
которая делает вид, что справилась, опаснее системы, которая говорит, где ей
нельзя доверять одной.

## Протокол валидации

Это то, что отличает работу от демонстрации. Правила проверяются автоматически и падают при нарушении.

1. **Разделение только по времени** — обучение до даты T, проверка после. Используется `submission_date`, а не `collection_date`: образец, собранный 1 ноября и депонированный 20-го, не был доступен системе 5 ноября.
2. **Кластеры родства не разрываются** — близкородственные изоляты не являются независимыми наблюдениями.
3. **Внешняя географическая валидация** — обучение на 22 странах, проверка на 23-й.
4. **Аугментация только после разделения и только в train** — проверяется тестом в CI.
5. **Словарь признаков строится только по обучающей части** — иначе тихая утечка.
6. **Калибровка на отдельной выборке**, не пересекающейся ни с обучением, ни с тестом.
7. **Обязательные базовые модели** — точка отсчёта не «случайное угадывание», а действующий стандарт.

## Целевые патогены

- ***Mycobacterium tuberculosis*** — лекарственная устойчивость. Приоритет №1: в Казахстане ~26 % новых случаев ТБ с МЛУ против 3,2 % в мире (ВОЗ).
- **SARS-CoV-2** — иммунное ускользание, ретроспективная проверка упреждения.
- ***Staphylococcus aureus*** (MRSA) — госпитальная передача и устойчивость.
